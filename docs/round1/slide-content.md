## Slide 1: "From isolated tickets to connected operations"

### Left: theme pill **POTENTIAL IMPACT**

Before → after table (6 rows, ~10 words each):

| # | Problem | Today | With OpsDesk |
|---|---|---|---|
| 1 | Context | Same refund raised 3x = 3 isolated tickets | One case graph: agency + TBOH + intent |
| 2 | Routing | Hardcoded FIFO/LIFO, mostly by country | Scored by region, time, rank, availability |
| 3 | Side convos | Recipients locked to group; break on transfer | Explicit recipient lists survive transfer |
| 4 | SLA & escalation | One-size SLA; escalate via followers/email | Check-in/LCD-aware clock + 1-click escalate |
| 5 | Insights | Locked in tickets; AI add-ons cost extra | Weekly themes, no paid add-on |
| 6 | Data & export | ~3K-row export cap; no realtime | Streamed, uncapped export + scale path |

Impact strip, label: **TARGETS WE WILL MEASURE IN THE PROTOTYPE** (no invented numbers):
Repeat contacts linked · Time to correct owner · SLA risk seen before LCD · Exports beyond the 3K cap · Zero per-add-on fees · Every decision explained

### Right: theme pill **INNOVATION**

| # | Card title | Body (words) | Tag |
|---|---|---|---|
| 1 | Case graph, not tickets | Agency + TBOH + intent linkage is first-class, with full history in one view. It replaces the separate third-party TBOH app. (21) | Solves P1 |
| 2 | Travel-aware SLA clock | Priority plus check-in/LCD proximity, with an optional regional-calendar flag, drives at-risk and breached. Not a generic timer. (19) | Solves P4 |
| 3 | Explainable routing + direct escalation | Scores region, time, rank and availability, and stores "why routed". One click escalates to the Escalation Manager. (18) | Solves P2 · P4 |
| 4 | Transfer-proof threads + insight loop | Side-conversation recipients survive reassignment. Conversations roll up into weekly themes without a paid AI add-on. (16) | Solves P3 · P5 |

Bottom ribbon (pitch line): *OpsDesk replaces isolated tickets with context-rich, travel-aware operations cases: linked by agency and TBOH, routed by reality, escalated on purpose.*

## Slide 2: "Built to ship in weeks, safe to adopt"

### Left: theme pill **IMPLEMENTATION AND TECHNICAL FEASIBILITY**

Architecture diagram (native shapes; source `docs/round1/architecture.mmd`, export `assets/architecture.png`):

- **Web app**: Angular · role-based views → **REST API**: auth, role checks, validation
- **Simulated TBO** (dashed, amber = seed/mock boundary): agencies · TBOH · calendars → REST API
- REST API → **Services**: Linkage · Routing engine · SLA engine · Side-conversations · Insights · Export
- Services → **PostgreSQL** (cases · links · audit) · **Outbox events** → realtime WS / poll · **Streamed export** → replica, warehouse

Stack line: **Stack:** Angular · NestJS (Node.js) · PostgreSQL: one TypeScript stack for two builders.

MVP → Problem map: MVP-1 · P1 Linkage · MVP-2 · P2 Routing · MVP-3 · P3 Side convos · MVP-4 · P4 SLA · MVP-5 · P5 Insights · MVP-6 · P6 Data export · MVP-7 · all Roles

Timeline (chevrons): **Round 1:** Idea + plan → **Round 2:** Working slice A–E → **Finale:** Polish + live demo

Team strip: **Team of 2:** **Karthikeyan** frontend & architecture · **Nandhini** backend, rules engines & data. *Two builders, one focused vertical slice.*

### Right: theme pill **ADOPTION RISK/FEASIBILITY**

| Risk | Likelihood* | Mitigation |
|---|---|---|
| Data migration from Zendesk | Med | CSV/API import, then dual-run |
| Agent change fatigue | High | Familiar queues, keyboard-first UI, guided link suggestions |
| Routing mistrust | Med | Visible "why routed", manual override, audit log |
| SLA misconfiguration | Med | Versioned rule config + simulation view |
| Scale limits | Low | Streamed export; replica / CDC path documented |
| Security & data leaks | Low | Role-based access, per-agency isolation, no hardcoded secrets |

Footnote (10 pt): *\*Our estimate before the pilot; re-rated with prototype evidence.*

**LOW-RISK ROLLOUT:** 1 Pilot one region / queue → 2 Shadow-run beside Zendesk → 3 Expand queue by queue

Bottom ribbon: *Cost contrast: own a single data path vs paying per add-on / per TPS API.*
