## Slide 1: "From isolated tickets to connected operations"

### Left: theme pill **POTENTIAL IMPACT**

| # | Problem | Today | With OpsDesk |
|---|---|---|---|
| 1 | Context | Same refund 3x = 3 isolated tickets | Case graph: agency + TBOH + intent |
| 2 | Routing | Hardcoded FIFO/LIFO, mostly by country | Scored: region, time, rank, availability |
| 3 | Side convos | Tied to group; break on transfer | Recipient lists survive transfer |
| 4 | SLA | One-size SLA; escalate via email | LCD-aware clock + 1-click escalate |
| 5 | Insights | Locked in tickets; AI add-ons cost extra | Weekly themes, no paid add-on |
| 6 | Data | ~3K-row export cap; no realtime | Streamed, uncapped export + scale path |

**TARGETS WE WILL MEASURE IN THE PROTOTYPE** (no invented numbers):
Repeat contacts linked · Time to correct owner · SLA risk seen before LCD · Exports beyond the 3K cap · Zero per-add-on fees · Every decision explained

### Right: theme pill **INNOVATION**

| # | Card title | Body | Tag |
|---|---|---|---|

## Slide 2: "Built to ship in weeks, safe to adopt"

### Left: theme pill **IMPLEMENTATION AND TECHNICAL FEASIBILITY**

Architecture diagram (native shapes; source `docs/round1/architecture.mmd`, export `assets/architecture.png`):

- **Web app**: Angular, role-based views → **REST API**: auth, role checks, validation
- **Simulated TBO** (dashed amber = seed/mock boundary): agencies, TBOH, calendars → REST API
- REST API → **Services**: Linkage · Routing engine · SLA engine · Side convos · Insights · Export
- Services → **PostgreSQL** (cases · links · audit) · **Outbox events** → realtime WS / poll · **Streamed export** → replica, warehouse

**Stack:** Angular · NestJS · PostgreSQL: one TypeScript stack for two builders.

MVP map: MVP-1 Linkage · MVP-2 Routing · MVP-3 Threads · MVP-4 SLA · MVP-5 Insights · MVP-6 Export · MVP-7 Roles. Caption: *MVP-n solves Problem n · MVP-7 secures all six*

Timeline: **Round 1:** Idea + plan → **Round 2:** Journeys A–E → **Finale:** Polish + live demo

Team strip: **Team of 2:** **Karthikeyan** frontend & architecture · **Nandhini** backend, rules & data. *Two builders, one focused vertical slice.*

### Right: theme pill **ADOPTION RISK/FEASIBILITY**

| Risk | Likelihood* | Mitigation |
|---|---|---|
| Data migration from Zendesk | Med | CSV/API import, dual-run |
| Agent change fatigue | High | Familiar queues, keyboard-first, guided links |
| Routing mistrust | Med | Visible "why routed", override, audit log |
| SLA misconfiguration | Med | Versioned rules + simulation view |
| Scale limits | Low | Streamed export; replica / CDC path |
| Security & data leaks | Low | Role-based access, agency isolation, env secrets |

Footnote: *\*Our estimate before the pilot; re-rated with prototype evidence.*

**LOW-RISK ROLLOUT:** 1 Pilot one region / queue → 2 Shadow-run beside Zendesk → 3 Expand queue by queue

Bottom ribbon: *Cost contrast: own a single data path vs paying per add-on / per TPS API.*
